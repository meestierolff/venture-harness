# ROADMAP

- Status: FOUNDER ALPHA — first real dogfood launch pending
- Owner: harness maintainers
- Last updated: 2026-08-09

## Purpose

Finish and prove the smallest trustworthy founder launch factory. Keep optional
advanced work coherent without turning it into a dependency of the one-prompt
web rail.

## Now — close v0.2 alpha

1. Keep the exact founder command, installed CLI and agent prompt on one
   implementation path.
2. Keep `founder-default` credential-free, doctorable, and bound to exact
   provider accounts and writable capture targets.
3. Keep the ordinary Next.js seed standalone, independently buildable, and free
   of the delegated-service runtime unless the venture needs it.
4. Keep the definitive Exception Desk Golden Path on the real CLI, child graph,
   provider SDK/transports, migrations, seed runtime, source publication path,
   primary journey, report, and Core upgrade.
5. Run the frozen release gate, repair P0/P1/P2 failures, push the branch, and
   leave a draft PR unmerged.
6. Publish no stable tag until one narrow real founder venture reaches a
   provider-backed production URL with sanitized read-back evidence.

## First dogfood gate

Use the simplest useful production test: a narrow private-repository web SaaS,
one authenticated journey, Neon, one Stripe **test-mode** price, one Brevo
transactional template, GA/Search setup, and manual DNS if necessary. It should
avoid native subscriptions, delegated customer providers, paid distribution,
Fleet, and any destructive migration.

Required evidence:

- complete real `founder-default` doctor without credential exposure;
- reviewed production dry run and immutable Launch Grant;
- independent GitHub repository with the expected commit;
- reachable stable Vercel production URL;
- Neon migration and health read-back;
- Stripe test resource/webhook read-back;
- Brevo, Google and Bing state reported as verified or precisely waiting;
- custom domain attached or one exact DNS action while the Vercel URL works;
- primary journey, desktop/mobile, accessibility, raw HTML and consent checks;
- honest final report and a dry-run Core upgrade preserving venture-owned work.

The dogfood run may expose an exact external provider action. It must not turn
that waiting state into success.

## Severity policy

| Priority | Fix before alpha handoff                           | Examples                                                                                                               |
| -------- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| P0       | Yes                                                | Secret leak, tenant escape, uncontrolled effect, data loss, unsafe migration, false production claim                   |
| P1       | Yes                                                | One-prompt command broken, child/repository/push/deploy absent, primary journey broken, upgrade corrupts venture files |
| P2       | Yes when implementable; otherwise explicit blocker | Missing provider diagnostic, recovery gap, missing release docs, weak verification                                     |
| P3       | No                                                 | Provider breadth, advanced Fleet, Winner Loop expansion, hosted features, internal cosmetic work                       |

## Later — optional, evidence-gated

- Move compatibility adapters into package capability contracts as real
  consumers migrate.
- Promote iOS from experimental after a signed build and TestFlight read-back;
  do not wait for public App Store approval to improve the web rail.
- Use recursive tenancy, Connection Hub, Service Blueprints and generated Agent
  Surfaces only for a demonstrated delegated-service venture.
- Exercise a real two-venture Fleet canary before considering automated
  low-risk merge; deployment remains separately authorized.
- Connect Winner Loop providers only after rights, disclosure, attribution,
  account, subscription and Growth Contract evidence exists. Publication and
  spend remain distinct human checkpoints; V1 never auto-scales.
- Keep knowledge graphs opt-in for a proven relational retrieval need.

## Explicitly not on the v0.2 path

- a public provider marketplace or dozens of adapters;
- a hosted multi-tenant Venture Harness SaaS or enterprise control plane;
- a generic no-code/visual workflow builder;
- automatic registrar support without a supported interface;
- automatic ad scaling, cross-platform budget allocation or VBO before
  readiness;
- every mobile framework, language SDK, or speculative agent identity system.

## Evidence

Current evidence is indexed by [Feature Status](FEATURE_STATUS.md) and
[Product Truth](PRODUCT_TRUTH.md). No live provider, customer, demand, revenue,
indexation, delivery, or advertising result is roadmap evidence.

## Assumptions

- Core remains open source and founder-operated; every child remains an
  independent repository in founder-owned accounts.
- `founder-default` stays opinionated until real launches demonstrate a missing
  capability.
- Reversible local improvements can proceed while external effects remain
  blocked on exact authorization.

## Unresolved questions

- Which founder-owned domain and provider accounts will be used for dogfood?
- Which provider will be the first genuine external waiting boundary?
- Which reviewed Core patch will exercise the first real child upgrade?
