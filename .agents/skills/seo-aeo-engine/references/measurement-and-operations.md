# Discovery measurement and operations

## Source order

Resolve conflicts in this order: product truth; approved offer/pricing;
approved repository profile; growth/content docs; production pages; raw HTTP;
normalized provider data; current primary research; historical reports; model
assumptions. A query never overrides product truth.

## Normalized dataset contract

Direct connectors are primary; manual imports are an explicit fallback. Each
dataset/row retains source, source account/property/site, `fetched_at`, reporting
window, timezone, dimensions, quality status, sampling/threshold limitations,
and release version when relevant. Missing is not zero. Do not combine
incompatible windows, infer conversions from clicks, or commit raw exports by
default.

Supported inputs may include GSC, GA4, Bing Webmaster/AI Performance, Neon
commercial evidence, Stripe, RevenueCat, Brevo, App Store analytics, releases,
and safely classified/de-identified feedback, interviews, and support.

## Opportunity scoring

Score user value, product relevance, commercial intent, traction, qualified
outcomes, wedge fit, original-value potential, diagnostic confidence, effort,
maintenance, and risk to winners. Scores support judgment and always include
written reasoning. Use P0 for blocked discovery, P1 for high-confidence core
opportunity, P2 for useful moderate evidence, P3 for monitor/test, and reject
for insufficient truth, evidence, relevance, or value.

Each recommendation records owner/cluster, user task, representative query,
current/proposed URL or store field, evidence period, metrics or `not
available`, diagnosis, change, original contribution, expected user/business
effect, confidence, effort, risk, verification, monitoring, and approval.

## Recovery

For a material decline, define the incident window and affected segments;
compare equivalent periods; inspect releases, migrations, crawl/index/render,
ownership/content, demand, seasonality, attribution, and provider quality;
record evidence for and against each hypothesis; take conservative reversible
actions; protect unaffected winners. A before/after change alone is not causal.

## New-site option

For `validate_first` or a new domain, 30/60/90 days may remain a useful optional
cadence: establish crawl/measurement/entity/first wedge; deepen its useful
decision coverage; then learn, consolidate, and expand carefully. There is no
fixed sandbox period or guaranteed result date.

## Report

Write scope/mode/profile, sources/windows/quality, executive finding, protected
winners, emerging opportunities, technical/content/store findings,
consolidations/rejections, ranked bounded actions, implemented diffs,
verification, approvals, monitoring, and unresolved uncertainty. If a command,
server, credential, or dataset is missing, state the exact gap, fallback
evidence, next command, and expected proof.
